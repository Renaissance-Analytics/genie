# Genie 2.0.0-beta.60

**This release stops Genie crashing while agents work, and brings it back safely if it ever does. Please update.**

## What's new

### Crashes
- **Your agents run apart from the window.** Agents, sites, updates and GitHub watching now run in Genie's background service. A busy window no longer slows them down, and a problem in the window no longer stops them.
- **Long agent work no longer fills memory.** Genie keeps a bounded history for each agent and shows previews of very large tool output. Open the full output when you want it.
- **After a crash, Genie starts in safe mode.** Nothing starts on its own: no agents, sites, flows or scheduled tasks. A banner lists what was running, and you start each item when you're ready.
- **A frozen window comes back.** If the window stops responding for 30 seconds, Genie records what was happening, closes it and opens a new one. Your agents keep running. If it freezes again within a few minutes, you can stop all agents in one click.
- **Send a crash report.** After a crash or a freeze, you can send a report to help us fix it. You see exactly what will be sent and can edit it first. Paths, names and secrets are removed, and nothing is sent without your click. Reports are filed on [fow-support](https://github.com/Renaissance-Analytics/fow-support).

### Agents
- **Add another agent** to a workspace that already has one.
- **Switching an agent's provider keeps its conversation.** A switch is never refused, except when the provider isn't installed or signed in, and then the reason shows with Retry.
- **The Genie agent can reach every agent again.**
- **A warning before a rate limit.** When an agent's provider account has 10% or less left in any limit window, the agent is told at the end of its turn, with the share left, so it can keep its next steps small and lose less work if it's paused.

### Workspaces
- **A workspace you haven't trusted stays that way, however Genie was stopped.** If the list of servers a workspace configures changes while Genie is starting, Genie waits until the list settles and asks again, rather than trusting a half-written list.
- **A git read that runs past its time limit is ended with everything its hooks started,** on Windows and Linux.

### Windows
- **Signed by Renaissance Analytics.** Genie, its installer and its helper are signed, so Windows shows who made them.
- **Genie's background service starts clean.** It no longer holds on to anything the window had open, so a window reopened after a freeze can use everything it needs, and a git read cut off at its limit ends everything its hooks started.

### Linux
- **Genie asks to unlock your keyring when it starts,** then carries on. There's nothing to set up and no restart.

### Everything else
- **Question windows** don't scroll sideways, and several questions show as tabs.
- **A throwaway terminal** opens from the workspace header.
- **The Files editor** fills its pane for images too.

## Known limitations

- **macOS** isn't supported right now, and no macOS builds are published.
- **Linux keyring:** Genie unlocks a keyring with no password without asking. The password dialog for a protected keyring hasn't been confirmed on a test machine yet.
- **A message already handed to a Claude agent mid-turn** can still run after you stop it. Codex agents don't have this. (Carried over from beta.59: re-check before publishing.)

## How it was verified

Every change landed with a test that failed first. The release branch (`release/beta.60`) passed the full CI matrix on its final head: Linux and Windows unit suites, the Flows suite, the packaged builds for both, the background service started on plain Node, and three real-window runs (layout, trust, safe mode, a hung window, a crashed page).

**Windows**, on a fresh Windows Server 2025 machine per check, Genie running as a standard user in its own signed-in desktop:
- **Quit keeps your agents:** "Just close the UI" with three agents streaming left the background service and every agent running; opening Genie again reused them; "Shut down everything" ended all of it, terminals included, and Cancel ended nothing.
- **The window and the service are separate:** with 11 agents running, the service and all 11 outlived the window and kept working, and a new window picked up the same service and agents.
- **A crashed window comes back:** the page was reloaded with your agents still streaming, a notice and a crash report on offer; after three crashes in ten minutes Genie stopped retrying and offered Restart Genie, which brought the window back with the agents still running.
- **Safe mode** after a crash started nothing on its own.
- **The ArtBoard stays responsive:** opening a 2 MB image took 264 ms, listing 100 posts 246 ms, with the window never stalling more than 23 ms.
- **The full test suite** ran in that desktop session: 11,563 of 11,564 tests passed. The one that did not needs a symlink, which a standard Windows user without Developer Mode cannot create; it runs and passes on our build machines.
- **Your saved sign-ins:** Windows Credential Manager stored, read back and deleted a key in the signed-in session, and a key saved before a restart was still there after it.

**Linux**, on a test machine: the full suite, Flows, a real-window smoke, unlocking the keyring at start (locked to unlocked, for a keyring with no password), reading a 1 GB agent history (1.4 s, the window never more than 13 ms late), and a hung window coming back with its agents running.

**Signing:** a signed test build was checked for the Renaissance Analytics signature on Genie, its installer and its helper before release; the release itself is signed in the same protected step.
