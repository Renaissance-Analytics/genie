# Genie 2.0.0-beta.38

beta.38 is beta.37 for every platform: beta.37 published for Linux only, because one of its tests ran past its time limit on the Windows build machine (genie#1101). The app is the same; everything below is new since beta.36.

## What's new

### Adding a workspace works the way Genie 1 did

- **Open existing folder and Import from Git build a new `<name>.agi` workspace around your repos, and never touch
  them.** Genie 1's four steps are back: **Source**, **Repos**, **Knowledge** and **Workspace**. Genie works out
  whether the folder is one repo, a monorepo or a collection of repos, lets you include, exclude and rename each one,
  and decides where your notes and docs go. Your original folder is left exactly as it was: knowledge is copied, not
  moved.
- **Each repo comes in the way you choose:** from its own remote (**Origin**), from the copy on your disk (**Local**),
  or as a **fork** into an account or organization you pick. Genie waits for GitHub to finish the fork before it
  builds.
- **Import from Git lets you browse your repositories** (every repo your GitHub sign-in can reach, with search and
  Private / Public marks) beside the URL box, and a github.com SSH URL is cloned over HTTPS with your sign-in when
  the app covers that account.
- **Where the workspace is kept is your choice:** **None** (on this machine only — fully supported, the default when
  you're not signed in to GitHub), **GitHub** (pick the account or organization; Genie creates the private
  `<name>.agi` repository, or reuses one that already exists, and pushes it), or **Paste a URL**. If you linked a
  Tynn project, Genie also records the repository on it.
- **If a step fails, you still get your workspace.** "<name> is ready" says which step didn't finish (GitHub, the
  remote, the push or Tynn) in that service's own words, and offers to install the GitHub app where it's missing.
- **Link a Tynn project from any add**, New, Open existing folder or Import from Git, or **create the Tynn project
  right there** with its owner (you, an organization or a team). The link on New is back (beta.36 had lost it).
- **"It came with agents":** when a workspace you add already has agents in `.agents/`, Genie lists them and adopts
  the ones you pick. It won't take a name Genie reserves.
- **Env file name is back in Settings → General** (default `.env`, your Genie 1 setting carries over). Each new
  workspace keeps it, and Genie writes its service settings into that file, checking first that git ignores it.

## Security

- **On a host you share, only its owner can add a workspace,** since adding one can now create a repository on the
  owner's GitHub and record it on their Tynn.

## Known limitations

- **All of a workspace's agents share one Tynn agent token for now.** Each agent becoming its own Tynn agent, with
  its own token and settings kept in sync, is being built (Tynn first).
- **Genie still lets you create an agent named `tynn` or `genie`,** which Genie 1 refused (adding a workspace's own
  agents already refuses them).
- **The agents a workspace came with are offered only right after you add it,** not later from the workspace menu as
  in Genie 1.
- Creating a repository in an organization, forking, and listing your repositories were tested against a stand-in
  for GitHub, not against GitHub itself; anything GitHub refuses is shown in its own words.
- macOS builds are not published in this beta.
