# Genie 2.0.0-beta.61.3


**A hotfix for beta.61.x: your drones are reachable through Tynn again. Update every machine you connect to.**


## What's new

- **Drones connect to the Tynn relay again.** Since beta.61, a machine set up as a drone never opened its link to the Tynn relay, so it vanished from your Pilot's list and its share links said "not connected to Tynn". It now connects as before.
- **A drone that starts while Tynn can't be reached comes up by itself.** It tries again (from 5 seconds up to every 5 minutes) and says why in its log, instead of staying off until you toggled remote access.

## Known limitations

- **A Pilot on 61.2 or later can't open a drone still on beta.60.** The connect screen shows `"host.home" is not a bridge method`. Update the drone first; beta.62 names this in plain words and reconnects by itself after the drone updates.
- **A terminal can stop drawing** until you scroll or resize it. Close and reopen the terminal, or resize it.
- **The hang check can report an agent as stuck** when the whole machine stalls for several seconds (fixed in beta.62).
- **A broken Claude or Codex install is detected and named, not yet repaired from Genie.** Reinstall it with the vendor's installer for now.

## Not in this build

- Everything in beta.62: the phone UI (swipeable chat and work panels, answer every question, camera), the drone version message and auto-reconnect, background processes set to "never" staying stopped after a restart, CLI repair from Genie, the chat staying on the agent you picked, Remote access settings cleanup, question option cards, sent image thumbnails, the hang check under host stalls, Do Not Disturb in the header.
- Several accounts per provider (63), Genie Mail (64), Compliance (65).
- macOS.
