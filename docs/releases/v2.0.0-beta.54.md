# Genie 2.0.0-beta.54

## What's new

### No more freezes when agents start or stop
- **Starting or stopping an agent no longer freezes Genie.** On Windows, each start or stop used to read the whole process list on the window's own thread. That read took 2 to 20 seconds and could run up to four times per agent start. It now runs in the background. On a Windows test machine, 18 freezes of 2 to 20 seconds went down to none over 1 second.
- **Genie now records its own stalls.** Any pause over 1 second is written to `~/.genie/runtime/lifecycle.log` with what was running at the time. This also covers slow responses, an unresponsive window and crashes, so the next freeze can be named.

### Agents get their mail without you typing
- **App mail wakes an idle agent.** When a site, process or script sends mail to an idle agent, the agent gets a turn on its own about a second and a half later.
- **Busy agents:** an agent that's mid-turn gets one follow-up turn when it finishes.
- **Bursts:** several messages arriving together become a single turn.
- **Stopped agents:** a stopped manual agent isn't started; its mail waits and shows as uncollected.

### Rate limits at a glance
- **The rate-limit pill on the dashboard is now a button.** It shows the provider's logo and how much is left in the tightest window. It turns yellow at 30% or less and red at 10% or less.
- **Click it** to open a popover with a bar for each limit window and when each one resets.

### Fixes
- **Less Defender CPU:** Genie's Caddy no longer touches its lock files dozens of times a minute, so Microsoft Defender has far less to scan.
- **App inbox:** Laravel sites served with `php artisan serve` now get their inbox token.
- **Windows:** stopping a running command now waits until it has fully exited and released its folder.

## Known limitations

- **macOS** isn't supported right now, and no macOS builds are published.
- **Freezes while Genie is idle,** with no agents starting or stopping, aren't explained yet. The new stall log is there to catch the cause.

## How it was verified

- **Tests and CI:** every change merged with its tests failing first, then passing. Main's CI is green on every job, including Windows unit tests and packaging.
- **Test machines:**
  - before-and-after freeze measurements on Windows;
  - about 600 stopped commands on Windows with no locked folders;
  - live inbox-wake checks on Linux and Windows;
  - the full suite on the Linux test machine.
