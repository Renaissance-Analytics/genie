# Genie 2.0.0-beta.45

## What's new

### Each agent has its own Tynn key

Every Genie agent now talks to Tynn with a key of its own, instead of the workspace's one shared token.
- **Storage:** keys are kept encrypted by your operating system in a private vault, and an agent only ever receives its own.
- **Old shared token:** Genie stops writing it and removes it from `.mcp.json`, `.cursor/mcp.json` and `.codex/config.toml`. Your other servers and settings in those files stay as they are.
- **Pairing:** your Tynn sign-in moves to Tynn's newer scoped pairing. **If Genie was signed in to Tynn only through a browser session, pair it with Tynn again once** (Settings → Accounts → Tynn).

### The Dashboard

- **Click an agent** to open its chat beside the Dashboard. The Dashboard stays; the row's **Open agent** still opens its page.
- **Mail between agents** travels as a signal from the sender's row to the recipient's, with a ✓ once it has been read.
- **Row emoji**, for a few seconds after the agent:
  - **👍** gives a thumbs up;
  - **✅** finishes (imDone);
  - **🧞** uses a Genie tool (a terminal, tabs, a background process, a site, a service, a page, a flow).
- **Rate limits in the header**, one pill per provider: how much of the current window is left, with the reset time on hover.
  - To stay light while many agents report, a pill changes at most once a minute.
  - Change that in **Settings → General → Rate-limit refresh on the Dashboard**.

### Flows

- **Arm** now asks first. The question says what the flow will do on its own: its schedule, its next run, and each command and agent it reaches.
- **Delete** asks first too.
- **Edit** opens a flow in the same form, with schedule presets (every 15 minutes, every hour, weekdays at 09:00, …) and the next run in words. A flow with more than one step can't be edited in the form yet, and its Edit button says so.

### Agents and addresses

- **An agent's address is `name@workspace`**, for example `tynn-slave@tynn-ai`, and the OS agent is `genie@system`.
  - The provider is no longer part of any address, display or target.
  - Old `claude:name` addresses still work.
- **Codex agents resume when their limit lifts.**
  - Genie re-reads a held Codex login every 15 minutes, instead of waiting for the reset time Codex states, which can be days late.
  - A retried turn no longer gets stuck "retrying".
- **Recovering a session that started without its tools.** An agent whose session came up without Genie's or Tynn's tools (for example, Tynn busy during a restart) is restarted on the same conversation to reconnect. Genie tries twice at most, then says so in the chat.

### Faster with many agents

- Genie no longer builds updates for remote devices when none is connected. It also checks each agent once per Dashboard refresh instead of twice, and reads mail only when it changes. This cuts the work the window does on each update with many agents running. If it still lags for you, please say so: lag with many agents is still being worked on.
- **"Restart Genie to install"** shows a restart screen at once, naming what it is waiting for. The window no longer freezes while agents stop.

### Genie no longer jumps in front of other apps

A plugin tool (for example the spreadsheet or presentation tools) used to start a second copy of Genie instead of running the tool. That second copy pulled Genie's window to the front while you were working in another app. Plugin tools now run as they should (#871).

### Security

- A share-link guest could read the host's live pairing PIN, paired devices, share links and connections. Guests no longer receive any of these (#872). **If you have shared a link with someone you don't fully trust, revoke your shares and pair your devices again.**

### Smaller things

- **Notifications:** while Genie is in front, alerts show at the bottom left, clear of the chat. When Genie is behind other apps, Windows' own notifications are still used. Titles name the agent as `name@workspace`.
- **The tray icon** shows a dot while anything in the Deck is waiting for you.
- **The Genie browser** keeps each site's page when you switch to another site and back.
- **Settings pages** no longer crush a setting's description into a narrow column next to its control.

## Known limitations

- macOS is not supported right now, and no macOS builds are published.
- On Windows, an agent's first start in a Tynn-linked workspace can take a few seconds longer while its key's file permissions are set (#1212).
- Starting an agent still runs two short process scans that can briefly hold the window.
