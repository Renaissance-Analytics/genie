# Genie 2.0.0-beta.12

## What's new

- A multi-part, multi-select or free-text question from an agent is answered on the Deck where it is read: "Answer N questions" expands the item into a form in place — one fieldset per question, a note for the agent, one Answer button — and the Deck checks the answer (one pick per single-select, at least one per multi-select, only the options offered) before it goes back to the agent. Nothing navigates away.
- In the chat flyout, a parked approval is answered with A and D in the thread (never while you are typing), Stop sits beside Send while the agent's turn runs, and a session that broke ends the transcript with a red rule naming the failure.
- The Agent view's right column notes what the context bar means: when compaction is expected and which plan step to hand off before, the last compaction with its time and sizes, or when usage was last reported if the stream closed. The persona block shows the agent's AGENT.md path before the first turn, and an empty Stream offers Message ⌘J and Edit persona.

## Migration

Installs over any earlier Genie in place through the app's own updater (from beta.7 on, Genie finds this build by itself) or by running the installer. Genie 1 workspaces, agents (claude and codex) and settings are imported on the first boot from `%APPDATA%\genie\genie.db`, which is left untouched; v1's leftover processes are stopped. Nothing else changes between beta.11 and beta.12.

## About this build

A rebuild from an empty repository, not a branch of the old one. The one rule: **an agent is a session, never a
terminal** — `AgentEngine` has no `'pty'` member, so "agent on a pty" cannot be written.

Beta.12 continues the row-by-row build against the design board: the Deck answering a multi-part question in place,
the chat flyout answering a parked approval with A and D, and the Agent view right column's blocks as the board draws them. The
audit and what remains are in the envelope's `.ai/plans/genie-2-board-audit.md`.

## What is in it

- **Workspaces** — `.agi` envelopes; add from a folder, a git URL or a Tynn project with the plan shown before
  anything is written; folder classification, convert, import; schema stamping with backup and refusal on a newer
  revision; repo registry with branch chips and the stale-lock fix; per-workspace settings; hibernate; remove (the
  folder untouched); ops projects; the workspace page opening on its agents.
- **Agents** — register / start (reattach, never a second session) / stop / restart graceful or fresh / delete
  (unmount vs delete) / switch driver / sidecars / personas / modes / daily budgets / diagnose; the Agent view per the
  board with Stream, Files, Changes (declared) and Activity, Terminal, Files, Changes (observed).
- **Attention** — imDone with a handoff, ForceTheQuestion (survives a restart), DND, two lists per workspace,
  thumbsUp, openFileForUser, submitFeedback, sounds, a tray toast naming workspace and agent.
- **AgentInbox** — durable local mail; native transport verified at boot; two-tier access; long-poll; read receipts;
  attachments as byte copies; the human as a participant.
- **Chat** — the flyout, pinned or overlay: the transcript with speakers, the context line, thread chips, undelivered
  drafts kept, the one composer, approvals answered where the composer is.
- **Terminals, panels, files** — real ptys (fancy-term-host 0.10.0 / fancy-pty 0.1.3); multi-attach; hide vs close;
  suspend/resume; snapshots; terminal, code and plugin pane kinds in four layout modes; the workspace file panel.
- **Hosting** — `.gen` sites, background processes, shared and dedicated services, the managed toolchain, Flows.
- **Plugins, knowledge** — signed by default; tool code outside Genie's process; vetted panels; the Knowledge Graph.
- **Remote, mobile, sharing** — drive another machine; PIN pairing with a QR; the baton; the lock; share links served
  once; the phone: questions, agents, one agent's activity and composer, upload — no terminals.
- **Tynn, MCP, GitHub, updates, settings** — Tynn as optional identity; Genie's own MCP server on the loopback;
  config sync; the GitHub App in two steps; updates per §7 with automatic checks; two-step onboarding; settings in
  four groups, reachable from the rail and the tray.

## Known limitations — read before installing over v1

- **GApps and agents-in-TUIs are not in this build** (the owner's ruling). A TUI runs only as a Take Over window.
- **Two capabilities are in but unmeasured**: the external browser path's OS prompts and services against a real
  Docker — neither test machine can run them.
- **Genie 1 agents on other TUIs** (anything but claude and codex) are not imported; the first boot lists them.
- Every plugin is unsigned until a publisher key exists, so plugins install only in developer mode.
- There is no macOS build in this release: macOS support is dropped for now. Windows and Linux only.
- Still open from the board audit: the Stream's turn index and session timeline, the Dashboard's collaborator reveal and
  workspace-level fault row, the files panel's change times and line counts.

## How it was verified

Every row went red → green in a Linux test machine (WSL2), never on a developer's desktop; each pull request carries
its batch table. The Windows VM ran the unit suite, the fancy-pty leak gate, the window from dist and the installed
app driven over CDP (the rail, the workspace opening on its agents, the chat flyout, the Files and Changes tab bodies,
the Dashboard's doors, the Agent view header per the board), the in-place upgrade from the real 0.7.0-beta.342 and
2.0.0-beta.4 installers, and the installed app finding the next build on a feed without being asked.
