# Genie 2.0.0-beta.5

The first build of Genie 2 — a from-scratch rebuild in which **an agent is a session, never a terminal**. It replaces an installed `0.7.0-beta.342` or `2.0.0-beta.4` in place through the app's own updater; your data stays where it was.

## What is in it

- **Dashboard** — every agent in every workspace on one screen, grouped by workspace, sorted waiting → broken → working → idle. A board you read; the Deck is where you answer.
- **Agent view** — the Stream: one line per event (thoughts, tools, edits, plan, usage), the Inspector for a selected edit, lanes, inline approvals, `⌘⇧T` Take Over.
- **Deck** — the attention queue for approvals, resolved in place, plus the signal strip (including the update signal).
- **Workspace terminals** — real shells and builds, on a new terminal engine (`fancy-pty`) that leaves nothing behind when a terminal closes: 0 threads, 0 handles and 0.011 MB retained per closed terminal, measured on Windows, where the previous engine kept ~1 thread, ~18 handles and ~13 MB each.
- **Take Over** — a TUI in its own window, shown as an Observed row; never managed as an agent.
- **Updater** — checks the channel it publishes to, never downloads unasked, and before installing stops every process running from the install directory and reports what it stopped.
- **Upgrade from v1** — the real `0.7.0-beta.342` and `2.0.0-beta.4` installers were each updated to this build in place in a clean Windows VM: same install, same uninstall entry, old data untouched. Genie 2 keeps its own data in `~/.genie`.

## Known limitations in this beta — read before installing over v1

- **Agents cannot message each other yet, and cannot ask you questions through Genie.** AgentInbox, `imDone`, `ForceTheQuestion`, lists and knowledge are not in this build; the server they need is being built in Prism.
- **The Take Over window has no Genie MCP** (same dependency).
- **The Deck has one of its four sources** (approvals). Flows, hosting, services and the toolchain manager from v1 are not in this build.
- v1 settings are not carried over yet (the reader exists; the settings surface does not). The Geist fonts are not vendored.
- A provider binary installed under a path containing a space fails to start (a known Prism issue).
- The macOS build is unsigned. No human had opened an installer when this was cut; it was proven by automation in a clean VM.

If you rely on agent-to-agent messaging or Flows today, stay on `0.7.0-beta.342` until a later beta lists them here.

## How it was verified

In a clean Windows 11 VM and a clean Ubuntu 24.04 distro, never on a developer's desktop: 652 unit tests; a real Electron window driven through 40 checks on the built app and again on the installed app; an installed 0.0.0 updating itself to a 0.0.1 build with an agent running and a terminal open at the moment of install (exactly one pty helper under the install directory before, none after; no agent process survived or was revived); both v1 upgrade paths; a live scan showing a running agent adds no pty and a terminal adds exactly one.
