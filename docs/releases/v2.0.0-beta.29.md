# Genie 2.0.0-beta.29

## What's new

### Sites and services

- **PHP sites no longer stop by themselves.** A PHP site used to stop answering after 500 requests, because its
  worker exited and was never brought back. Workers now have no request limit, and a worker that exits for any
  reason comes back.
- **WebSockets work from https sites, at one secure address.** Every workspace reaches the shared WebSockets server at
  `wss://websockets.gen`, through Genie's front door and certificate. Each workspace keeps its own app on that server.
  Every key Genie gives a site (`REVERB_*`, `VITE_REVERB_*` and Genie's own) is `wss`/`https` on port 443. Live
  updates no longer fall back to polling.
- **A PHP site trusts Genie's own certificate.** The site's own PHP can now reach `https://` `.gen` addresses with the
  certificate verified, as Laravel's broadcaster does when it talks to `websockets.gen`. Genie adds its certificate
  authority for the site's PHP only. Your own `php.ini` is never touched.
- **A PHP site keeps answering when its databases change.** Adding, removing, choosing or detaching a workspace's
  engine restarts only the site's PHP worker, and the site waits for it instead of answering 502. A PHP worker that
  crashes is also waited for while it comes back.
- **A workspace's own custom engine keeps its database.** A custom image that sets its own database variables is
  no longer overridden by a shared Postgres beside it.

### Agents

- **Stop cancels the turn, not the agent.** "Stop this turn" sits on the chat's status line and next to the Agent
  view's state badge. Stopping the agent itself is "Stop agent" in its menu.
- **Agents start with their workspace's service variables.** An agent's own shell has the workspace's database,
  Redis and other service connection variables. Only those reach the agent: no tokens or other credentials Genie holds.
- **`services exec`.** An agent can run one command, such as a migration or a seed, with the workspace's current service
  variables. You approve the command first, and every credential in its output is masked.
- **Terminal commands run through the shell.** A command an agent starts in a terminal runs through the shell, so
  `&&`, pipes and quoting work, and its output can still be read after it finishes.
- **Agents can always reply.** An agent can answer another agent that wrote to it, across workspaces.

### Chat and the Agent view

- **The context meter shows how full the context really is.** It used to add up every call the agent made and kept
  growing; it now shows the latest figure.
- **No flash when switching agent tabs.** Switching agents in the chat shows that agent's conversation at once.
- **Turns are numbered once, in order.** No "Turn 1" after a restart, and a prompt the agent refused leaves nothing
  behind. It no longer leaves a "Working" state with a clock that never moves.

## Fixes

- **Lag:** saving an agent's conversation now appends the new row instead of rewriting the whole conversation file
  every time. Long conversations were rewriting megabytes per row.

## Known limitations

- **The window can still freeze briefly when an agent starts or stops.** Genie still scans running processes at those
  moments and waits for the scan. The fix is planned for the next release, together with sending only new rows to the
  window as an agent works.
- **Remote and sharing are not yet at Genie 1's level.** That covers Tynn workstation registration and tunnels, workspace and
  workstation sharing, and finding your Tailscale machines.
- **Adding a second workspace is not offered in the app yet.**
- **PHP sites run on php-cgi.** FrankenPHP as the default PHP server and Laravel Octane are planned.
- **Adding an engine can occasionally fail on a slow machine.** Genie gives most Docker commands 20 seconds, and creating
  a container can take longer on a busy machine. Asking again works. A fix is planned.
- **Many Genie 1 features are not in Genie 2 yet.** That includes the Ctrl+K Command Window, saved prompts, the F5 nudge
  hotkey, the Feedback hotkey and window, the choice of alert sound, IssueWatch and the Knowledge Graph editor. They are
  planned, starting with the Command Window, saved prompts and the hotkeys.
- **An agent that is already running keeps the service variables it started with.** It gets new ones from
  `services exec` or after a restart.

## How it was verified

- **The full unit suite passed,** with typecheck and the renderer build, in a Linux test machine. Every change was
  written test-first, and each test was watched failing before the fix went in.
- **PHP workers:** a php-cgi worker run the old way answered exactly 500 of 520 requests, and Genie's answers all 520.
- **moic's acceptance on the installed app,** in the Linux test VM:
  - the https site and its asset URLs;
  - pgvector, choosing an engine, detaching, a custom engine, and remove and add-back;
  - a real `wss://websockets.gen` connection through the front door, verified with Genie's certificate, that gets the
    WebSockets server's `connection_established`;
  - the site's own PHP reaching `https://websockets.gen` with the certificate verified;
  - the site answering straight after an engine change.
  - All 48 checks passed on the final build. One earlier run of the same build hit the Docker timeout above.
- **The PHP worker gap:** with the worker down for 1.5 seconds, a request got 502 within 8 ms the old way. With
  Genie's retry, the same request got 200.
- **Windows:** checked in the Windows test VM before tagging.
- **The first release built and published from the `genie` repository,** with that repository's own token.
