## What’s new

- **The Genie OS agent stops starting from scratch every time.** It could never record that setup had finished, because recording it required a check it was structurally unable to pass — so every launch announced itself as the workstation’s first boot. It can now do the things every other agent can: receive messages, file its own feedback, and finish starting.
- **An agent whose name clashes with another can be deleted.** Two agents sharing a name was the one situation where the agent could not be removed — and the single menu item offered, *“Resolve name conflict…”*, did nothing at all when clicked. Deleting one is how the clash gets settled, so that is what the menu now offers, and it says so.
- **Agents from before beta.292 stop asking permission on every launch.** Their saved start command still contained the flag that made Claude Code stop and ask; it is cleared the next time Genie starts, so they pick up the approved channel like everything else.
- **Agents are told how to orient themselves, instead of being told to re-read their own instructions.** Every agent used to start by being handed a list of instruction files to go and read — files its harness had already loaded for it. It is now pointed at the three things it genuinely cannot know: that it is connected to Genie, what its previous run left unfinished, and what the project expects of it.
- **An agent can leave a note for its own next run.** Restarts are constant — an upgrade, a crash, a closed terminal — and until now the next run began with nothing. An agent finishing can leave a handoff, and the next one is given it at launch.

## Migration

- No action is required.
- Two things are repaired on first launch: the saved start commands above, and the Genie OS agent’s own setup record.
