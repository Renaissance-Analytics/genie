# Genie 2.0.0-beta.57

**This release includes security fixes for Windows and for repos you add. Please update.**

## What's new

### Security
- **Windows: Genie finds programs by their full path.** Genie and the terminals it starts for agents no longer run a program just because it sits in a workspace folder. Your own terminals keep normal Windows behaviour.
- **A site's first start is yours.** A site a repo declares in `project.json` waits until you press Start, and shows you the command it would run. Sites you already had carry over. Changing a site's command, folder, serving mode, environment or port asks again.
- **Approval cards show every character** of what you're approving.
- **`services exec` keeps a line's quoting on Windows,** so a quoted path with a space runs the program you named.
- **The Tailscale installer runs only if Windows verifies it:** the signature has to be valid and from Tailscale Inc. Otherwise it's refused, with the reason.

### Chat
- **One reply is one bubble.** Replies no longer split mid-word when a subagent's tool call or a notice arrives between two pieces of text. Replies already recorded stay split.
- **A message the agent has answered no longer reads as queued.** The clock and "Interrupt and send" no longer show after the agent has replied. A long command with no reply yet still shows them.

### IssueWatch
- **The live feed connects to production.** Before, it was refused and retried every 5 minutes, which affected push notices, the counts in `imDone` and the GitHub panel.
- **A refusal now has a reason,** shown to agents and in the panel. Issues load even when the live feed is down.

## Known limitations

- **A site declared with `npm` can't start on Windows** (genie#1513). This isn't new, but it now says why in the site's log. A site that runs `node` directly works.
- **Adding a folder that isn't a full workspace replaces its `project.json`,** with no backup (genie#1510), so any sites it declared are lost.
- **Not proven:** a signed-in Genie reaching the live IssueWatch feed on production. That needs a real account.
- **IssueWatch refresh for large workspaces** can still time out on Tynn's side.
- **macOS** isn't supported right now, and no macOS builds are published.

## How it was verified

- **Tests and CI:** every change merged with its tests failing first, then passing. Main's CI is green on every job, including the real-window smoke on Linux and Windows and both installer builds.
- **Test machines:** the full test suite ran on the Linux and Windows test machines on this exact code, and the real-window smoke ran on the Linux test machine. A timing test's long gaps on the Linux test machine didn't appear in 30 repeats on GitHub's runners on either system, so they look specific to that machine. Why they happen isn't explained yet.
- **The real app:** on Windows, the installed beta.56 and a packaged build of this release were both run through adding a workspace, the Files tab, opening a file and the dashboard. Sites were checked on both as well.
