# Genie 2.0.0-beta.34

## What's fixed

### Agents get their AgentInbox mail again

- **An idle agent is woken by its AgentInbox mail.** In beta.33 an agent could show **Working** for an hour or more
  after it had stopped, because a message sent to it mid-turn was counted as a turn of its own that never ended.
  While it read Working, mail and your messages waited behind it. Now a turn ends when the agent's turn ends, and
  the agent is idle and reachable.

### Genie keeps up with a busy agent

- **No more lag beside a busy agent.** With an agent that had a long history (tens of thousands of steps), Genie
  took seconds to show text and over a minute to show a question. Each update an agent makes now costs the same
  however long its history is, and Genie sends the window only what changed.

### Adding a workspace works again, the way Genie 1 did it

- **Add workspace asks "How should Genie start?"**, from every place you can add one: New workspace, Open existing
  folder, Import from Git or Import from Tynn. In beta.33 it opened a bare file browser that could only take a folder
  that already existed and was empty, so a new workspace could not be made at all.
- **New workspace asks for a name and a folder,** shows where it lands (`…\name.agi`), and Genie makes the folder, the
  workspace and its first commit.
- **Open existing folder takes a plain folder too,** as Genie 1 did, without running `git init` in it.
- **Primary workspace is back in Settings → General** (your Genie 1 setting carries over). New workspaces start there,
  and folder pickers opened from the workstation open there; inside a workspace, they open in that workspace.

### Issue notices reach agents again

- **IssueWatch no longer stays off after a bad start.** If Tynn could not be reached the moment Genie started, Genie
  showed you signed out and never asked again, so no issue notices reached any agent. Now it asks again after 30
  seconds, 2, 10 and 30 minutes, when the computer wakes, and when an agent asks for its issues.

### Images in Files

- **An image opens as the image,** filling the pane, with no device frame around it. Video, audio and PDF open the
  same way.

### The Dashboard

- **A workspace's header stays on one line** in a narrow window; a long path is cut short instead of the name
  wrapping.

## What's new

### A paused account is caught, and you're told

- **When your provider pauses your account** (a billing problem, an account on hold, or subscription access turned
  off), every agent on it shows **Account paused** with the reason, instead of Broken or Signed out.
- **You get one desktop notification per account,** however many agents it stopped, saying what the provider
  reported and what to do.
- **Try again** (in the agent's header, the chat and the tray) brings every agent on that account back once the
  account is put right.

### Automated agents finish their plan

- **An agent set to automated mode doesn't stop with its plan unfinished.** When its turn ends with steps of its
  plan left, Genie tells it what's left and to carry on. It isn't nudged when you stopped it, while it's waiting on
  your answer or an approval, or when something else already reached it. If three nudges in a row complete no step,
  Genie stops nudging and says so in the chat.

## Changed

- **No "Genie 1" labels.** Things brought over from Genie 1 (a GitHub sign-in, flows, service engines) look like
  everything else.
- **AgentInbox mail in the chat is short:** who it's from and a two-line preview. Click it to read it in full in the
  AgentInbox.

## Known limitations

- **The Genie browser is still not Genie 1's.** It is a page in the menu, not its own window, and it can show a blank
  page; a site panel in a workspace tab does not load. It is being rebuilt from Genie 1's: its own window, Genie sites
  only, per connected computer, live site panels agents can manage.
- **The New workspace form doesn't yet offer Genie 1's optional Tynn project link or GitHub backup note.**
- **On Windows, stopping or restarting an agent can leave its old Claude process running** until Genie restarts.
  The fix is still in progress; it was not ready for this release.
- **Rarely, a Genie process can outlive Genie on Windows when Genie is force-closed.** Making every process Genie
  starts end with it is part of the same fix.
- **The mobile view shows a paused account but doesn't offer Try again;** use the desktop window or the tray.
- **Updating Genie still restarts everything,** including terminals, processes and sites. Updates that leave them
  running when only the window changed come in a later release.
- **Each PHP site still runs in a terminal of its own, behind its own Caddy.** One server for every site
  (FrankenPHP, PHP 8.5) is in progress.
- **Codex agents don't have Interrupt and send yet;** a message sent mid-turn waits until the turn ends.
- **Installing and choosing versions of Node, Python, Go, Ruby, Java, .NET and Rust** from the Toolchain is still to
  come.
- **Signing in to an agent provider is done in the provider's own window.**
- **A window driving another computer doesn't play the per-action sounds yet.**
- **On some Linux desktops the menu's own shortcuts don't fire.** Genie's keys work everywhere.
- **.odp presentations and .ods spreadsheets** open read-only or not at all until their formats are supported.
- **The Knowledge Graph editor from Genie 1 is not in Genie 2 yet.**

## How it was verified

- **Every change was written test-first,** its tests watched failing before the fix went in, and it passed all
  eight checks before it merged, including a real Genie window on Linux and on Windows.
- **The lag fix was measured:** each agent update over a 60,000-step history went from 55 ms of Genie's time to
  under 0.2 ms, and what Genie sends the window per update from 27 MB to 550 bytes.
- **The paused-account handling was built from the real failure** an agent hit on 2026-10-21, the provider's own
  error, not a guess at it.
- **The release commit, three full suite runs in a row** on the Omarchy test machine, with typecheck, and the
  release-notes check proven to fail when the notes are missing.
- **Windows, on the Windows test machine:** the unit suite, a real terminal with the leak check, a real window and
  the layout at six widths from the build; then the installer built, installed silently with both Start-menu
  shortcuts, the same window checks from the installed app, the sites checks through the front door, and a clean
  uninstall.
