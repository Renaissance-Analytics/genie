# Genie 2.0.0-beta.26

## What's new

- **Your `.gen` sites are served again.** Two faults stopped them; both are fixed.
  - **One site's own Caddy took the ports the others needed.** It held the web port and Caddy's admin port, so the other
    sites and Genie's front door could not start, and a certificate prompt appeared that nobody asked for. Each site's
    Caddy now holds only its own port.
  - **Static and PHP sites answered the front door with an empty page.** Each site's Caddy answered only requests
    addressed to `127.0.0.1`, while the front door asks for the site by its own name. Each site now answers its name
    and stays reachable from this machine only.
- **Services move to Genie 2 on upgrade.** Genie 1's databases, caches, Mailpit and MinIO are taken over in place:
  the same containers, data, ports and passwords, so your apps keep working with their existing `.env`. Genie 1's
  leftover workspace containers are stopped.
  - Adding Postgres or MySQL from the Services tab no longer fails partway through a download.
  - Ports stay the same across restarts.
  - Genie checks every service when it starts, and says "Docker is not running" when that is the problem.
- **Agents' questions open on top of every window.** When an agent asks you something, the question opens in its own
  window above everything else, one question at a time. Pending Questions lists the same questions and stays in step
  with it.
- **The Deck shows what agents are asking you.** It was empty.
- **A turn an agent starts on its own shows as working,** for example when a background task finishes. It used to read
  Idle.
- **Turn numbers count up one at a time.** A message you send while an agent is working is numbered when its own turn
  starts, so numbers no longer repeat or skip.
- **The Changes tab shows what an agent changed.** It listed nothing for Claude agents, because each edit is saved
  as several rows and the tab never put them together.
- **The chat follows you.**
  - Pinned, picking an agent's tab opens that agent.
  - Floating, it stays on the same conversation while you move around the app.
- **Agents can see which other agents are running.** `agentinbox list` says whether each peer is working, idle,
  failed or stopped, and when it was last active. Asking never starts anyone.
- **The Agent view:**
  - The Turns column collapses to just the turn numbers, and Genie remembers your choice.
  - "Following live" moves to a status bar under the stream, off the stream's text.
  - "Find in stream" is never cut off.
  - Scrollbars are thin everywhere.

## Migration

Installs over any earlier Genie in place; the header's update notice does it. No data changes.

## Known limitations

- **Not yet imported from Genie 1:** open to-dos.
- **Agents cannot add or manage services and sites through Genie's tools yet.** You can, from Hosting.
- **Some Genie 1 sites are listed but not served yet:** container sites, multi-label `.gen` names, frankenphp or
  octane, and pinned PHP versions. Each row says why.
- **Agents cannot add or manage background processes yet.**
- **Claude's reasoning text is not shown.** Current Claude models send their thinking with the text omitted.
- **GApps and agents-in-TUIs are not in this build** (the owner's ruling).
- Windows and Linux only; no macOS build.

## How it was verified

- **Every change went red → green** in a Linux test machine (WSL2), never on a developer's desktop. New code was also
  broken on purpose to prove its tests catch it, then restored.
- **The site fix was measured against the real Caddy** that Genie ships. Before the fix, the request the front door
  sends got an empty page. After it, the site's own page comes back, and the site cannot be reached from outside the
  machine.
- **The Windows VM** builds the installer, installs it and drives the installed app. Two `.gen` sites must answer
  through the front door with their own pages, no site's Caddy may hold the web or admin port, and launching Genie
  must add no trusted certificate.
- Every Windows run now starts from a snapshot taken after a clean shutdown, so a run that froze cannot affect the
  next one.
