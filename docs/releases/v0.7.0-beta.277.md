# Genie gets a real first-run experience

This release turns a fresh Genie install into a guided workstation setup and completes the managed-workspace and AMS migration contracts.

## What’s new

- A first-run **Getting the Workstation Ready** flow chooses model drivers first, installs only the base Git/Node toolchain plus the selected supported drivers, requires Tynn sign-in, offers GitHub as optional, verifies the setup, and finishes by adding the first workspace.
- Genie now recognizes Claude Code, Codex, Kiwi Code, and the Genie TUI as first-class agent providers. Automatic readiness is gated on each harness’s native AgentInbox transport; terminal input is never used for agent-to-agent delivery.
- Every workstation has a built-in **Genie** OS agent. It has workstation-operator authority, lives outside all projects, and refuses direct project work so the project’s Workspace Agent remains the owner.
- Every expanded project now has an obvious **New Agent…** action in the workspace sidebar. It opens the complete provider, identity, access, wake, and IssueWatch form instead of hiding agent creation inside the Add Terminal menu.
- Expanded workspaces now use one **Add Panel…** launcher for terminals, files, agents, and enabled plugin panels such as ArtBoard and Repository. Plugin choices create real `plugin-panel` surfaces instead of terminal lookalikes.
- Background-process and hosted-site status now share one compact two-sided pill in each workspace row. The left and right halves carry status by colour; clicking the pill opens the existing Process and Site Manager destinations.
- Genie-managed `AGENTS.md` and `CLAUDE.md` routers now use `@` imports and point only at the shared protocol plus their own harness guide. Claude no longer receives a Codex guide link, or vice versa.
- **Add Workspace** now starts with exactly three choices: New workspace, Import from Tynn, and Import from Git. All create managed workspaces; the old plain-folder path is gone.
- Tynn workspace imports use Tynn’s declared envelope repository metadata, clone it, inspect `project.json`, and refuse to register a mismatched source.
- Old agent terminals can call `agentUpgrade` for the in-place AMS migration guide. The guide binds the existing conversation instead of creating a replacement agent.
- GDWs receive a focused skill for building GApps and moving `project.json` and `gapp.json` to current shared schemas.
- The canonical GApp manifest is now `gapp.json`. This is a hard cut: Genie no longer reads `genie-app.json` as a compatibility alias.
- Genie and Tynn now consume `Civicognita/shared-schemas` v0.2.0. Legacy v0.1.1 `project.json` files are backed up, migrated atomically, and preserve unknown fields.
- Tynn’s Genie page now ships every screenshot it references, with a regression test that fails when an asset is missing or empty. Its Add Workspace copy now matches the managed wizard.

## Migration

- Workspace files: Genie's next schema-aware write creates one timestamped backup, preserves unknown fields, and stamps the v0.2.0 `project.json` schema.
- GApps: if `genie-app.json` exists, back it up and rename it to `gapp.json` only after validation. If both filenames exist, stop and resolve the conflict; Genie will not guess.
- Existing agent terminals: call `agentUpgrade`, bind the current harness session, verify its native transport, then call `thumbsUp` with `reason: "boot"`.

No repository release, installer, tag, or update-feed change is performed by this implementation commit; those remain behind the release approval gate.
