# Genie 2.0.0-beta.43

## What's new

### Genie's own Node

- **Settings → Toolchain → Node versions** installs Node 24.22.1 (the current LTS) into Genie's own toolchain folder.
  The zip comes from nodejs.org and is checked against the SHA-256 nodejs.org publishes before anything is written.
  An install counts only when `node -v` reports that version and its own npm runs; a failed install leaves nothing
  behind. Installed versions can be removed from the same place.
- A Node you install there becomes the one Genie runs. Terminals and agents pick it up when Genie next starts, and
  every start after that.
- **Check and repair** now finds a node or npm that is not Genie's winning on your PATH (for example Herd's), and puts
  Genie's own first for what Genie runs. It judges npm by what `npm -v` actually answers. If Genie's own npm does not
  run, it says so and moves nothing. If Genie has no Node yet, it says where to install one.
- Genie gives its processes and agents their own npm prefix, so Node's `npm` cannot hand over to an npm installed under
  another prefix (an inherited `npm_config_prefix`, or a `.npmrc` `prefix=`). `npm install -g` from an agent goes into
  Genie's own `npm-global` folder.
- Agent sessions now receive Genie's npm prefix and PHP certificate settings by name. Other environment variables are
  still withheld from agents.
- Your own PATH and `.npmrc` are never changed.

### Agents

- The workspace's Agents roster lists agents that are **Registered** and those **On disk only**, with **Reattach** for
  an agent whose folder is present but is not registered.
- The built-in genie agent always has full access and no permission settings; every agent can reach it.
- A resumed Codex agent no longer writes its earlier history into Genie's chat a second time.

### Safer agent credentials

- Updated the provider bridge to prism-acp 0.25.0. A session's own MCP credential now takes precedence over a
  `bearer_token_env_var` inherited from your Codex configuration, and it is kept out of the session's thread
  configuration, shell snapshots and commands the model runs.

### Services

- Service images can be updated in place from Services, with the interruption shown and approved first and the service
  recovered afterwards.

## Known limitations

- Genie installs its own Node on Windows only. On macOS and Linux it uses the Node on your PATH.
- Per-agent Tynn credentials are not switched on yet; agents still use the workspace's shared Tynn connection.
- Several screens still recompute over an agent's whole history on each update; very long histories can still be
  noticeable.
- macOS builds are not published in this beta.

## Verification

- Windows test VM, Genie's own Node end to end: 15 of 15 checks passed with the real nodejs.org download. A tampered
  checksum was refused and left nothing behind; Node 24.22.1 installed and its own npm ran. Check and repair put
  Genie's node and npm ahead of another node and a shadowing npm; `npm -v` then answered Genie's npm; the order was
  restored at the next launch; a broken npm was reported and not moved; and Remove worked. Before the npm prefix
  change the same run failed 1 of 14: another npm answered.
- A real Codex 0.163 agent on Windows received Genie's npm prefix and PHP setting, and an unrelated secret stayed
  withheld. With the allow-list bypassed, the same check failed first.
- prism-acp 0.25.0 was checked against real Codex 0.163 and Claude 2.1.310 processes, with no model inference or
  sign-in. On 0.24.1 two checks failed first: a session credential reached the thread configuration and environment
  snapshots. On 0.25.0 all the credential checks passed.
- The Omarchy (Linux) test VM ran 5,624 tests (5 skipped) across 757 files, plus typecheck and production builds.
- Windows and Linux CI passed unit tests, real-window smoke tests and packaging on the release commit.
