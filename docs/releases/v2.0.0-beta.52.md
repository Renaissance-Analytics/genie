# Genie 2.0.0-beta.52

A hotfix release.

## What's new

### PHP sites can make HTTPS calls again
Since beta.50, every outbound HTTPS call from Genie-managed PHP failed after Genie restarted (cURL error 60, "unable to get local issuer certificate"). That broke model APIs, webhooks and Packagist.
- **How it's fixed:** Genie exports your machine's trusted root certificates to a CA bundle. Every managed `php.ini` points `curl.cainfo` and `openssl.cafile` at it after an install, after a restart and after a version switch, as Genie 1 did.
- **Your own CA file is safe:** a CA file you set yourself is never replaced.
- **Windows:** site workers now trust public hosts too, not only Genie's own `.gen` certificate.

### Shared services attach to any workspace
Adding a shared service that already exists, for example the shared Mailpit, now attaches it to your workspace. Before, Genie answered "exists" and left the workspace without it. Once attached, `use` and `start` work and the workspace's sites get its settings (for Mailpit, the `MAIL_*` variables).

## Known limitations

- **macOS** isn't supported right now, and no macOS builds are published.
- **Online dots:** the workstation list shows "unknown" for a machine until Tynn's presence check is live everywhere.

## How it was verified

- **Tests first:** both fixes merged with their tests failing first, then passing. Main CI is green on every job, including Windows unit and packaging.
- **PHP fix on the Windows test VM:** a real PHP 8.4.27 reproduced the cURL error before the fix. After it, HTTPS to api.anthropic.com and example.com verifies after install and after a restart (15/15 checks). A control run with the old `php.ini` still fails.
- **Linux test VM:** the full suite passed.
