# Onboarding that meets you where you are

This release repairs the first-run and workspace-import experience, gives Genie OS a proper home, and makes AgentPanels directly manageable from the Floor.

## What’s new

- Existing Genie users can finish onboarding immediately when their workstation already has workspaces. Adding another workspace is offered, never forced.
- The GitHub step now distinguishes “connected” from “installation discovery failed.” Organization installations load visibly, Refresh retries the real request, and failures no longer masquerade as an empty account.
- **Import from Git** includes a repository browser covering every repository exposed through every Genie GitHub App installation, including accounts with more than 100 repositories.
- **Import from Tynn** recognizes both managed envelope repositories and ordinary Tynn projects with a code repository. A load failure is shown as an error instead of “No importable Tynn workspaces.”
- New, GitHub, Tynn, and local-folder sources now converge on the interactive scanner wizard. Genie inspects the source before writing anything and detects existing `.agi` and `.gapp` envelopes instead of wrapping them inside a second envelope.
- The local New flow again lets you point at an existing project folder, review the detected repositories and knowledge, choose the host repository, and approve the managed workspace plan.
- The built-in **Genie OS** agent now owns a dedicated `genie-os.agi` workspace with git history and private `.ai/memory`, rather than using the user’s home directory as its working folder.
- Onboarding shows the Genie OS workspace and can create a private `genie-os.agi` GitHub repository, attach it as origin, and push the initial workspace for backup.
- Genie OS no longer appears as a workspace-sidebar project. Its wand lives in the application header and opens a smooth slide-out AgentPanel over the current workspace; clicking outside slides it closed.
- A live Genie OS session is visible through animated header state, and the open flyout uses a moving border light so workstation activity is unmistakable without occupying project space.
- Every project AgentPanel now has a dedicated **Restart agent** button. Right-clicking the panel opens agent-specific actions for **Agent settings…** and **Restart agent**.
- Agent restarts use the existing guarded resume path: supported Claude and Codex conversations reconnect to current tools, while missing or unsupported session state is refused rather than silently discarding context.

## Migration

- No project workspace migration is required.
- Genie creates the Genie OS workspace automatically on first launch after updating and moves the built-in workstation agent’s working directory there.
- GitHub backup for Genie OS is optional and can be configured during onboarding.
