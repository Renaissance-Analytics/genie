# Genie 2.0.0-beta.58

**This release asks you to trust a workspace before it runs what its files declare. Existing workspaces carry over as trusted once.**

## What's new

### Trusting a workspace
- **A workspace is untrusted until you say so.** A step at the top of the workspace shows what it would run: its sites, hooks, servers and git settings. Say yes, and the step goes.
- **A change asks again.** If the list changes, for example after a pull, Genie asks before going further.
- **Your existing workspaces carry over as trusted,** once, so nothing stops working when you update.
- **Agents in an untrusted workspace ask before shell commands,** even if they're set to all tools. They use your own settings rather than the workspace's. Codex agents also lose your own skills there, unless you name one in a message.
- **Git reads have a time limit.** A read that runs past it shows as a failure you can see, in the Files tab, on the dashboard and in the add-workspace wizard.

### Sites
- **Sites declared with `npm` start on Windows.** Stop leaves nothing running.
- **Adding a folder keeps its `project.json`,** so the sites it declares stay.

### Agents
- **An agent working in the background shows as Working,** in the dashboard's groups and counts, its dots and the rail. Only an idle agent reads as idle.
- **A paused agent answers its mail automatically,** so the sender knows it's paused rather than waiting.

### IssueWatch
- **An item is announced as new once.** Old issues, PRs and Tynn feedback no longer come back as new whenever the list moves.

### Windows
- **Programs named inside Genie's scripts go by their whole path,** including elevated steps.

## Known limitations

- **Codex in an untrusted workspace** hasn't run on a real sign-in here. Claude has.
- **A trust change during a turn** applies when that turn ends.
- **Items created while Genie is closed** aren't announced when it next starts.
- **A reopened item** isn't announced unless you've turned on updates, and a list count can read short for a busy repo.
- **macOS** isn't supported right now, and no macOS builds are published.

## How it was verified

- **Tests and CI:** every change merged with its tests failing first, then passing. Main's CI is green on every job, including the real-window smoke on Linux and Windows and both installer builds.
- **Test machines:** the full test suite ran on the Linux and Windows test machines, and the real-window smoke on Linux, on this code apart from the IssueWatch fix. That fix is one file, tested on both systems in CI.
- **The real app:** on Windows, a packaged build was run through adding a workspace, the Files tab, opening a file, the dashboard and sites declared with `npm` and with `node`.
- **A real Claude sign-in:** a development build of this code ran an agent as untrusted on a real login. It didn't read the folder's instructions or skills, kept Genie's words and tools, a shell command waited for approval and ran once allowed, and a resumed conversation held up, including one that began trusted.
