# Genie 2.0.0-beta.25

## What's new

- **Your Genie 1 AgentInbox history is here.** Genie 2 imports Genie 1's agent mail once, on its next start: messages
  between you and your agents, and between agents, with their attachments. Each attachment is copied and checked
  against Genie 1's file.
  - History arrives as read, so nobody is flooded with old notices. The exception is mail Genie 1 never delivered
    in the last week: it stays unread.
  - Agents can page back through their history.
  - Genie 1's channel broadcasts and its system and schedule notices are not imported. Genie 2's inbox is one-to-one
    and has no machine senders. The import notes how many were left out.
- **Your Genie 1 background processes are here.** Genie 1's processes are imported once into Hosting → Processes.
  - Only the ones Genie 1 would have started, and you had not stopped, start.
  - Hibernated workspaces still wait.
  - Scheduled jobs belong to Flows and are not imported; each one is noted.
- **The Genie Browser is in the sidebar.** It opens your `.gen` sites, and any web address, including your tailnet's
  machines and Tynn sites.

## Migration

Installs over any earlier Genie in place; from beta.22 on the header's update notice does it. On the first start,
Genie 1's AgentInbox history and background processes are imported once. Genie 1's database is only read.

## Known limitations

- **Not yet imported from Genie 1:** service engines (databases, Redis) and open to-dos. Genie 1's database still
  holds them.
- **Some Genie 1 sites are listed but not served yet:** container sites, multi-label `.gen` names, frankenphp or
  octane, and pinned PHP versions. Each row says why.
- **Agents cannot add or manage background processes yet.** Genie 1's `manageProcess` tool is not in Genie 2.
- **Files cannot be sent to an agent on another workstation, or to a Take Over window, yet.**
- **Claude's reasoning text is not shown.** Current Claude models send their thinking with the text omitted.
- **GApps and agents-in-TUIs are not in this build** (the owner's ruling).
- Windows and Linux only; no macOS build.

## How it was verified

- **Every change went red → green** in a Linux test machine (WSL2), never on a developer's desktop. New code was
  also broken on purpose to prove its tests catch it, then restored.
- **The imports were projected on a real Genie 1 database**, read-only and counts only, before shipping.
- **A guard test** fails if any surface Genie can show has no labelled way in. It now derives that list from what
  Genie serves, instead of keeping a typed copy.
- **The Windows VM** builds the installer, installs it, and drives the installed app.
