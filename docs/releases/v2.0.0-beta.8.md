# Genie 2.0.0-beta.8

## What's new

- Workspaces are listed by name (from each envelope's `project.json`, else the folder), never by id.
- Workspaces you hibernated in Genie 1 arrive hibernated, including on a machine that already upgraded.
- The theme follows your system by default, and the Theme setting (dark, light, system) is honoured everywhere — including the chat composer.
- Settings has a row in the rail and an item in the tray menu; the app and the tray carry Genie's own icon.

## Migration

Installs over any earlier Genie in place through the app's own updater (from beta.7 on, Genie finds this build by itself) or by running the installer. Genie 1 workspaces, agents (claude and codex) and settings are imported on the first boot from `%APPDATA%\genie\genie.db`, which is left untouched; v1's leftover processes are stopped. A machine already on beta.6 or beta.7 gets its Genie 1 hibernation applied once at the next boot.

## About this build

A rebuild from an empty repository, not a branch of the old one. The one rule: **an agent is a session, never a
terminal** — `AgentEngine` has no `'pty'` member, so "agent on a pty" cannot be written.

Beta.7 was the owner's first build with workspaces in it; the first minutes found ids where names belong, hibernation
ignored, a white composer on a dark app on a light desktop, no way to Settings, and the default icon. Beta.8 is those
five fixes, each proven in the Linux test machine and then in the Windows VM on the real window and the installed app.

## What is in it

- **Workspaces** — `.agi` envelopes; add from a folder, a git URL or a Tynn project with the plan shown before
  anything is written; folder classification, convert, import; schema stamping with backup and refusal on a newer
  revision; repo registry; per-workspace settings; hibernate; remove (the folder untouched); ops projects.
- **Agents** — register / start (reattach, never a second session) / stop / restart graceful or fresh / delete
  (unmount vs delete) / switch driver / sidecars / personas / modes / daily budgets / diagnose.
- **Attention** — imDone with a handoff, ForceTheQuestion (survives a restart), DND, two lists per workspace,
  thumbsUp, openFileForUser, submitFeedback, sounds, a tray toast naming workspace and agent.
- **AgentInbox** — durable local mail; native transport verified at boot; two-tier access; long-poll; read receipts;
  attachments as byte copies; the human as a participant.
- **Terminals, panels, files** — real ptys (fancy-term-host 0.10.0 / fancy-pty 0.1.3); multi-attach; hide vs close;
  suspend/resume; snapshots; terminal, code and plugin pane kinds in four layout modes; the workspace file panel.
- **Hosting** — `.gen` sites, background processes, shared and dedicated services, the managed toolchain, Flows.
- **Plugins, knowledge** — signed by default; tool code outside Genie's process; vetted panels; the Knowledge Graph.
- **Remote, mobile, sharing** — drive another machine; PIN pairing with a QR; the baton; the lock; share links served
  once; the phone: questions, agents, one agent's activity and composer, upload — no terminals.
- **Tynn, MCP, GitHub, updates, settings** — Tynn as optional identity; Genie's own MCP server on the loopback;
  config sync; the GitHub App in two steps; updates per §7 with automatic checks; two-step onboarding; settings in
  four groups, reachable from the rail and the tray.

## Known limitations — read before installing over v1

- **GApps and agents-in-TUIs are not in this build** (the owner's ruling). A TUI runs only as a Take Over window.
- **Two capabilities are in but unmeasured**: the external browser path's OS prompts and services against a real
  Docker — neither test machine can run them.
- **Genie 1 agents on other TUIs** (anything but claude and codex) are not imported; the first boot lists them.
- Every plugin is unsigned until a publisher key exists, so plugins install only in developer mode.
- There is no macOS build in this release: macOS support is dropped for now. Windows and Linux only.

## How it was verified

Every row went red → green in a Linux test machine (WSL2), never on a developer's desktop; each pull request carries
its batch table. The Windows VM ran the unit suite, the fancy-pty leak gate, the window from dist and the installed
app driven over CDP (native window buttons, drag region, the `genie` row, the rail naming the workspace, the Settings
row, the theme following the OS with the composer on the same side of it), the in-place upgrade from the real
0.7.0-beta.342 and 2.0.0-beta.4 installers with a seeded, hibernated Genie 1 workspace imported asleep and an orphaned
shell reaped, and the installed app finding the next build on a feed without being asked.
