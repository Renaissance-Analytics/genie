# Genie 2.0.0-beta.24

## What's new

- **Hosting, Toolchain and AgentInbox are back in the sidebar.** They were built, but no row, icon or palette entry
  led to them. Hosting holds your Sites, Processes and Services.
- **Background processes you keep.** In Hosting → Processes, add a process: workspace, command, an optional folder
  inside the workspace, and a restart policy.
  - It starts at once, and comes back every time Genie starts.
  - Your Stop is kept through restarts until you press Start. Genie quitting is not a Stop.
  - Remove forgets it.
  - A hibernated workspace's processes wait, and the row says why.
- **Your sites are back.** Genie 2 now reads the sites each workspace's `project.json` declares, the same list
  Genie 1 served. They show in Hosting → Sites, with Start and Stop.
  - As in Genie 1, enabled sites in awake workspaces start when Genie starts, unless you stopped them. Your Stop
    is remembered on this machine only, never written into the envelope.
  - Waking a workspace starts its sites.
  - A site you add or remove in Genie 2 is written back to `project.json`. Only the `sites` entry changes; every
    other key, and the file's formatting, stays as it was.
  - A site Genie 2 cannot serve yet is listed with the reason, not hidden: container sites, names with more than
    one dot before `.gen`, frankenphp or octane, a pinned PHP version.
- **Your Genie 1 knowledge is here.** Genie 2 now imports Genie 1's knowledge graph (memories and their links) once,
  on its next start. It reads Genie 1's database without changing it, and never overwrites a memory you have
  edited in Genie 2.
- **The Knowledge Graph shows its memories when you open it.** Before, it showed loading placeholders until you
  searched.
- **Hibernated workspaces are hidden in the sidebar.** "Show hibernated · N" beside WORKSPACES shows them, and
  Genie remembers your choice. The workspace you are looking at always stays visible.
- **Doctor mode works while Genie is open.** It can start an agent in any awake workspace where Genie has no agent
  started. It works on its own copies of Genie's data, so neither overwrites the other. While doctor runs that agent,
  Genie will not start another agent in the same workspace.

## Migration

Installs over any earlier Genie in place; from beta.22 or beta.23 the header's update notice does it. On the first
start, Genie 1's knowledge graph is imported once.

## Known limitations

- **Not yet imported from Genie 1:** background-process definitions, AgentInbox history, service engines and
  open to-dos. Genie 1's database still holds them.
- **Some Genie 1 sites are listed but not served yet:** container sites, multi-label `.gen` names, frankenphp or
  octane, and pinned PHP versions. Each row says why.
- **Agents cannot add or manage background processes yet.** Genie 1's `manageProcess` tool is not in Genie 2.
- **Files cannot be sent to an agent on another workstation, or to a Take Over window, yet.**
- **Claude's reasoning text is not shown.** Current Claude models send their thinking with the text omitted.
- **GApps and agents-in-TUIs are not in this build** (the owner's ruling).
- Windows and Linux only; no macOS build.

## How it was verified

- **Every change went red → green** in a Linux test machine (WSL2), never on a developer's desktop. New code was
  also broken on purpose to prove its tests catch it, then restored.
- **A guard test** now fails if any surface Genie can show has no labelled way in.
- **The Windows VM** builds the installer, installs it, and drives the installed app; its screenshots now come back
  for a person to look at.
