# Genie 2.0.0-beta.63

**Connecting to other people's hosts works: share links open Genie straight into the host or workspace, the Host button works again, and remote connections stay up. The toolchain page tells the truth, and Flows no longer drop their prompts.**

## What's new

- **Share links open Genie.** Opening a share link now hands off to Genie and opens a window on that host, or on just the shared workspace. A host you reached through a link is for that session only and no longer appears among your own hosts.
- **A shared workspace's window shows only that workspace**, with its own terminals and folders. A read-only share shows terminal output only, and can't stop or interrupt an agent's turn.
- **The Host (Connect) button opens the host picker again.**
- **Remote connections stay up** when an update is too large to send in one piece. The other side fetches it instead of the connection closing.
- **Flows wait their turn.** A flow that fires while its agent is busy is queued and runs as soon as the agent's turn ends. It is never dropped, and firing again replaces the waiting prompt instead of stacking a second one.
- **Toolchain:** Codex is no longer reported as broken when npm's launcher uses Node from your PATH, and Composer's Update works (it updates itself).
- **Hosting pages are compact.** Services, Sites and Processes rows fit on one line, with the main action as an icon and everything else in a row menu. Removing anything asks first and says plainly what is kept or deleted. "In use" is a table, and adding a process opens a proper form.
- **Agents ask you through the question window, not in chat.** Questions are no longer left in chat replies where they get missed.
- **No internal ids on screen** in chat, mail, the Deck, the inbox, the stream or notifications.
- **Agents' settings live in the workspace's `project.json`**, and an agent's `AGENT.md` holds only its persona.
- **The sidebar can list every agent**, so you can pick one without switching workspaces.
- **A workspace share can reach only that workspace**, and a read-only share can change nothing.
- **Windows Firewall:** the Remote access row shows whether Genie's rule exists, and can remove it.
- Fixes: Genie's window no longer uses ever more memory over time; a raw "unhandled promise rejection" no longer appears in the Deck while Genie restarts; the Tynn relay status is shown correctly; a failed update check no longer hides the Upgrade button; Tailscale sign-in on Linux drones works; long Tynn board labels no longer squeeze card titles; a flow's agent turn now finishes properly instead of staying "working".

## Good to know

- **Window size and position reset once** after upgrading, because Genie's windows now load from a local web address (this is what makes passkeys possible later).
- Both sides of a remote connection should be on beta.63 for large updates to come through.

## Not in this build

- The Genie host building its features with no window open (it's being finished), and updates that leave your agents running while only the window updates.
- Several accounts per provider and switching accounts.
- The Toolchain version picker for PHP and Node, a "Check for updates" button, and toolchain updates during Genie's own upgrade.
- Slash commands typed in chat (like /compact), the plan popover, Dashboard window shortcuts, running flows in the header, the sound picker preview, and opening pending questions when Do Not Disturb ends.
- Agents stuck showing "Working" after they stop (a fix is coming with the next agent library update).
- macOS.
